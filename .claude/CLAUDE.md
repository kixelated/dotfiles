# Communication

- Prefer simple, concise output. Include only details that help me decide or act.
- When a step doesn't need my input, keep going. Put status notes in the same message as your next action.
- Stop and ask only when intent or a consequential choice is unclear, or before anything destructive. Brainstorm options and use an interactive prompt with a recommendation.
- Prioritize refactoring for long-term code maintainability.
- Pro-actively do any background research and explore the state-of-the-art. Mark anything you couldn't confirm, and say where you looked.

# GitHub

- Every GitHub post you author must end with a `(written by <model>)` line naming the running model. This is separate from the `Co-Authored-By` trailer on commits.
- Don't comment on repos I don't maintain without approval.

# Reviews

- List only problems you'd block the merge for, each with file and line.

# Loops

- Back out when minimal progress is being made, rather than burn tokens.
- For long multi-step work, keep a `TASKS.md` checklist updated as you go so progress survives context summarization.

# Development

- Default to worktrees.
- Focus on simplification.
